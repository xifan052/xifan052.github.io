常用前端知识积累

闭包的理解

使用闭包主要是为了设计私有的方法和变量。优点是可以避免全局变量的污染，缺点是闭包会常驻内存，会增大内存使用量，使用不当很容易造成内存泄露。

Cookie

数量限制

  • 每个特定的域名下最多生成20个cookie：
    • IE6或更低版本：最多20个cookie
    • IE7及之后版本：最多50个cookie
    • Firefox：最多50个cookie
    • Chrome和Safari：没有硬性限制

大小限制

  • cookie的最大大小约为4096字节，为兼容性考虑，一般不超过4095字节。

优点

  1. 扩展性和可用性：
    • 控制保存在cookie中的session对象的大小。
    • 通过加密和安全传输技术（SSL），减少cookie被破解的可能性。
    • 只在cookie中存放不敏感数据。
    • 控制cookie的生命期，使之不会永远有效。

缺点

  1. Cookie数量和长度的限制。
  2. 安全性问题：如果cookie被人拦截，即使加密也无济于事。
  3. 有些状态不可能保存在客户端，例如防止重复提交表单的计数器。

浏览器本地存储

sessionStorage

  • 存储一个会话（session）中的数据，仅在同一个会话中的页面可以访问，会话结束后数据销毁。

localStorage

  • 用于持久化的本地存储，除非主动删除数据，否则数据永远不会过期。

web storage与cookie的区别

  • Cookie：
    • 每次请求都会发送，浪费带宽。
    • 需要指定作用域，不可以跨域调用。
    • 需要前端开发者自己封装setCookie、getCookie。
  • Web Storage：
    • 不会随每次请求发送，节省带宽。
    • 无作用域限制，可以跨域调用。
    • 更加简洁易用。

link 和 @import 的区别

  1. 类型：
    • link属于HTML标签，而@import是CSS提供的。
  2. 加载时机：
    • 页面加载时，link会同时加载，而@import引用的CSS会等到页面加载完再加载。
  3. 兼容性：
    • @import只在IE5以上识别，link无兼容问题。
  4. 权重：
    • link方式的样式权重高于@import。

box-sizing属性

box-sizing属性主要用来控制元素的盒模型解析模式，默认值是content-box。

  • content-box：
    • 元素的宽度/高度由border + padding + content决定，设置width/height属性指的是content部分的宽/高。
  • border-box：
    • 设置width/height属性指的是border + padding + content。

BFC规范的理解

BFC（块格式化上下文）是一个渲染机制，内部元素与外界互不干扰。

创建BFC

  • float的值不是none
  • position的值不是static或relative
  • display的值是inline-block、table-cell、flex、table-caption或inline-flex
  • overflow的值不是visible

BFC特性

  • 内部的BOX会在垂直方向上一个接一个放置。
  • 相邻的两个BOX的margin会发生重叠。
  • 每个元素的左外边距与包含块的左边界相接触。
  • BFC区域不会与浮动元素区域重叠。
  • 计算BFC的高度时，浮动子元素也参与计算。
  • BFC是页面上的一个隔离容器，内部子元素不影响外部元素，反之亦然。

BFC在布局中的应用

  • 阻止margin重叠：将两个元素放在不同的BFC中。
  • 包含浮动子元素：通过创建BFC（如设置overflow: hidden）来包含浮动子元素，防止高度塌陷。
  • 多栏布局：利用BFC特性实现左右两栏固定宽度，中间栏自适应的布局。

null和undefined的区别

undefined

  • 表示“无”的原始值，转为数值时为NaN。
    • 变量被声明但未赋值。
    • 函数参数未提供。
    • 对象未赋值的属性。
    • 函数没有返回值。

null

  • 表示“无”的对象，转为数值时为0。
    • 作为函数参数表示该参数不是对象。
    • 作为对象原型链的终点。

document.write和innerHTML的区别

  • document.write：只能重绘整个页面。
  • innerHTML：可以重绘页面的一部分。

HTML5的离线存储

原理

HTML5的离线存储基于.appcache文件的缓存机制，通过这个文件上的解析清单离线存储资源。

使用

  1. 在文档的html标签设置manifest属性，如manifest="/offline.appcache"。
  2. 在项目中新建manifest文件，命名建议为xxx.appcache。
  3. 在Web服务器配置正确的MIME-type，即text/cache-manifest。

CSS各种居中

水平居中

.parent {
  text-align: center;
}
.child {
  display: inline-block;
}

.child {
  display: table;
  margin: 0 auto;
}

.parent {
  position: relative;
}
.child {
  position: absolute;
  left: 50%;
  transform: translateX(-50%);
}

垂直居中

table-cell配合vertical-align

.parent {
  display: table-cell;
  vertical-align: middle;
}

absolute配合transform

.parent {
  position: relative;
}
.child {
  position: absolute;
  top: 50%;
  transform: translateY(-50%);
}

水平+垂直居中

inline-block配合text-align加上table-cell配合vertical-align

.parent {
  display: table-cell;
  vertical-align: middle;
  text-align: center;
}
.child {
  display: inline-block;
}

absolute配合transform

.parent {
  position: relative;
}
.child {
  position: absolute;
  left: 50%;
  top: 50%;
  transform: translate(-50%, -50%);
}

全能的flex

水平居中

.parent {
  display: flex;
  justify-content: center;
}

垂直居中

.parent {
  display: flex;
  align-items: center;
}

水平+垂直居中

.parent {
  display: flex;
  justify-content: center;
  align-items: center;
}
